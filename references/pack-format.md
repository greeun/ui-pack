# Pack format

This is the format the `ui-pack` scripts read (`scripts/install.py`, `scripts/build-view.py`, `scripts/gallery-check.mjs`, `viewer/`) and the `ui-pack-create` skill writes. An existing pack in the pack store is the best worked example when there is one.

Packs live in the pack store at `$UI_PACK_HOME/packs/<pack>/`. `UI_PACK_HOME` defaults to `~/.axt/vault/ui-pack`.

## Folder layout

| Path | Content |
| --- | --- |
| `pack.json` | The pack definition (below) |
| `README.md` | What each folder holds, which components the pack has, and how it differs from other packs |
| `guide/ui-direction.md` | The design guide (below) |
| `tokens/globals.css` | The tokens: CSS variables and the Tailwind 4 `@theme` blocks |
| `tokens/layout.example.tsx` | Example root layout that loads the fonts |
| `tokens/vitest.config.example.mts` | Minimal vitest config for the pack tests |
| `fonts/` | Font files and their license files |
| `lib/` | `ui-pack-config.ts`, and `theme.ts` when the pack has a theme switch |
| `components/` | The components, `motion/` for motion components, `design/Gallery.tsx` for the gallery |
| `gallery/page.example.tsx` | The gallery page (`/design` in the target) |
| `tests/` | Token contrast tests and component logic tests |
| `patterns/` | Optional. Reference patterns: components tied to the source app's domain. They are not installed; a target rebuilds them for its own domain from their structure and classes |
| `view/` | Generated by `build-view.py`: `index.html` (the pack viewer, one file), `preview-light.png`, `preview-dark.png`. Never edited by hand |

`$UI_PACK_HOME/packs/index.html` (the pack index) is also generated by `build-view.py`, from every `*/pack.json` next to the pack.

## pack.json

```json
{
  "name": "example-pack",
  "version": "1.0.0",
  "description": "White cards on a soft gray background, for settings and admin screens. Light theme only.",
  "origin": {
    "mode": "inspired",
    "inputs": [{ "kind": "url", "ref": "https://example.com/", "captured": "2026-01-15" }],
    "credit": "example.com",
    "brand": { "terms": ["Example"], "colors": ["#4b3cdf"], "fonts": [] },
    "estimated": []
  },
  "requires": { "react": ">=19", "next": ">=16 (App Router)", "tailwindcss": ">=4", "typescript": ">=5", "pathAlias": "@/* → source root (src/ or the project root)" },
  "dependencies": { "motion": "14.14.0" },
  "devDependencies": { "vitest": "^4" },
  "install": [
    { "from": "tokens/globals.css", "to": "{src}/app/globals.css", "mode": "replace-or-merge" },
    { "from": "tokens/layout.example.tsx", "to": "{src}/app/layout.tsx", "mode": "merge" },
    { "from": "fonts/", "to": "{src}/app/fonts/", "mode": "copy" },
    { "from": "lib/", "to": "{src}/lib/", "mode": "copy" },
    { "from": "components/", "to": "{src}/components/", "mode": "copy" },
    { "from": "gallery/page.example.tsx", "to": "{src}/app/design/page.tsx", "mode": "copy-and-adjust" },
    { "from": "tests/", "to": "tests/", "mode": "copy" },
    { "from": "tokens/vitest.config.example.mts", "to": "vitest.config.mts", "mode": "copy-if-missing" },
    { "from": "guide/ui-direction.md", "to": "docs/design/ui-direction.md", "mode": "copy-and-adapt" }
  ],
  "config": "{src}/lib/ui-pack-config.ts",
  "optional": {},
  "sources": {},
  "packOnly": [],
  "viewer": { "gallery": "@/components/design/Gallery#Gallery", "guide": "guide/ui-direction.md", "background": "var(--paper)" },
  "components": {
    "color-tokens": { "status": "present", "files": ["tokens/globals.css"], "gallery": "Color tokens" },
    "dark-theme": { "status": "absent", "note": "The source has no dark theme" },
    "spinner": { "status": "unused", "note": "Loading is shown as text" }
  },
  "changes": [{ "version": "1.0.0", "notes": ["First version"] }]
}
```

(`components` is shortened here. A real pack lists every id in `catalog.json`.)

| Key | Meaning | Read by |
| --- | --- | --- |
| `name`, `version`, `description` | Identity of the pack. Shown in the pack viewer and the pack index, written to `ui-pack.lock.json` | `install.py`, `build-view.py`, viewer |
| `source` | `{ "repo": "<path of the source project>", "commit": "<commit the pack was last synced to>" }`. Only for a pack extracted from a project's source code | viewer (shows the folder name and the commit), `ui-pack-create` sync |
| `origin` | Only for a pack made without source code (from a URL, SNS post, image or video). `mode` is `"faithful"` (faithful pack) or `"inspired"` (inspired pack). `inputs[]` is `{ kind, ref, captured }` with `kind` one of `url`, `sns-post`, `image`, `video`. `credit` names the original author or site; a faithful pack has `rights` instead. `brand` is `{ terms, colors, fonts }` (things unique to the source; `fontsNote` / `colorsNote` when they cannot be known). `estimated` lists values that were estimated, not measured | viewer (mode, credit, input kinds, estimated), `ui-pack-create` origin check |
| `requires` | The stack the target needs. `install.py` compares the major version of `react`, `next` and `tailwindcss` with the target's `package.json` and stops with exit code 2 when the target is lower or lacks the package. Other keys (`typescript`, `pathAlias`) are information for the reader | `install.py`, viewer |
| `dependencies`, `devDependencies` | Packages installed into the target as `name@version` with the target's package manager, when the target does not already list them | `install.py`, viewer |
| `install` | The files to copy, in order: `{ from, to, mode }` (below) | `install.py`, `build-view.py`, viewer |
| `config` | Path of the config file in the target, with `{src}`. `install.py --name` rewrites `productName` in it | `install.py`, viewer |
| `patterns` | A sentence that explains the files in `patterns/`. Omit when the pack has none | viewer |
| `optional` | Optional groups: `{ "<group>": ["<pack-relative file>", ...] }`. `install.py --without <group>` skips those files. A string value next to a group (such as `"logout_note"`) is a note and is ignored. Use `{}` or omit when there is no group | `install.py`, viewer |
| `sources` | Map from pack path to source-project path, used by `ui-pack-create` to find source changes. `{}` for a pack without source | `ui-pack-create` |
| `packOnly` | Pack files that have no counterpart in the source project | documentation only |
| `viewer` | Pack viewer settings. `gallery` (required): the gallery component as `module#export`. `themeSwitch` (omit when the pack has one theme): the theme switch component as `module#export`. `guide`: path of the design guide in the pack. `background`: CSS background of the sticky table of contents, e.g. `var(--paper)` | `build-view.py`, viewer |
| `components` | Status per component id of `catalog.json` (below) | `build-view.py` (pack index), viewer |
| `changes` | Change log: `[{ "version", "notes": [] }]`, newest first | documentation only |

### install entries

`{src}` in `to` becomes `src` when the target has a `src/` folder, otherwise the project root. A `from` that ends with `/` is a folder: every file under it is copied, always as `copy`.

`install.py` treats three cases differently and everything else as a plain copy. The other mode names tell the person or agent what to do after the copy.

| `mode` | What `install.py` does | What follows by hand |
| --- | --- | --- |
| `copy` | Copies the file | Nothing. The file is not edited in the target |
| `replace-or-merge` | Copies the file (used for `globals.css`) | Carry over the target's own rules from the `.before-pack` file where needed |
| `merge` | Does not touch the target file. Writes the pack file next to it as `<name>.pack-example` (used for `layout.tsx`) | Merge the example into the target file |
| `copy-and-adjust` | Copies the file (used for the gallery page) | Adjust small things such as the route's title |
| `copy-and-adapt` | Copies the file (used for the design guide) | Adapt it to the target as the guide's pack note says |
| `copy-if-missing` | Skips when the target folder already has a file with the same base name, whatever the extension (used for `vitest.config.mts`) | When skipped, align the `@` alias in the existing config |

For every copied file: an existing target file with different content is kept as `<name>.before-pack` on the first install; a file the user edited after the install (its hash differs from `ui-pack.lock.json`) is left untouched on later installs.

Two paths are fixed in the scripts:

- `tokens/globals.css`: `--keep-defaults` comments out the lines `--color-*: initial;`, `--text-*: initial;`, `--radius-*: initial;`, `--shadow-*: initial;` in this file only. Write each of them on its own line.
- `tests/`: when the target has no `src/` folder, `"../src/app/globals.css"` in these files is rewritten to `"../app/globals.css"`. That is the only relative path the script fixes, so tests import components through the `@/` alias.

`build-view.py` takes the layout from the `install` entry whose `mode` is `merge` and whose `to` ends with `app/layout.tsx`, and removes `src/app/design`, `tests`, `docs` and `vitest.config.mts` from the viewer build, so keep those destinations as in the example.

### components and status values

`components` has one entry for every item id in `~/.claude/skills/ui-pack/catalog.json` (the component catalog): `{ "status", "files"?, "gallery"?, "note"? }`. An id that is missing is shown as `absent`.

| `status` | Meaning | Other fields |
| --- | --- | --- |
| `present` | The pack has the component (or class) and a gallery card for it | `files`: pack-relative files. `gallery`: the title of its gallery card |
| `rules-only` | No component; the design guide only has rules for it | `note` |
| `absent` | Not there yet. A target builds it from the design guide's rules when needed | `note` (optional) |
| `unused` | The pack's design leaves it out on purpose | `note`: the reason |

A component that is hard to show as a gallery card (the app shell, the page title, the theme switch) may be `present` without `gallery`.

## Tokens (`tokens/globals.css`)

Every pack defines these names, so the mapping in `SKILL.md` and the components of one pack can be read against another:

| Token | Use |
| --- | --- |
| `--paper` | Page background |
| `--surface` | Card surface |
| `--ink` | Text |
| `--ink-2` | Secondary text |
| `--rule` | Lines and borders |
| `--accent` | Accent color. An older pack may use another name tied to a meaning (inkpaper uses `--mark`, "waiting for the user"); its README says so |
| `rounded-*` | Radius, as `--radius-<name>` in `@theme` (for example `rounded-control`, `rounded-panel`, `rounded-pill`) |
| `shadow-lift-*` | Shadow, as `--shadow-lift-<n>` in `@theme` (for example `shadow-lift-1`, `shadow-lift-2`) |
| `text-<size>` | Type size, as `--text-<px>` in `@theme` (for example `text-14`) |

Other tokens (`--raised`, `--sunken`, status colors, motion durations) are added when the design has them. The colors are mapped into Tailwind with `--color-<name>: var(--<name>)` in `@theme inline`, after `--color-*: initial;` clears the default palette so that no color outside the tokens can be used.

A pack with a dark theme defines the dark values under `@media (prefers-color-scheme: dark)` for `:root:not([data-theme="light"])` and again for `:root[data-theme="dark"]`; `<html data-theme>` is how an explicit choice is applied. A pack with one theme sets `color-scheme` to that theme, records `dark-theme` as `absent` and omits `viewer.themeSwitch`.

## Common files the install and the pack viewer need

- `lib/ui-pack-config.ts`: exports `UI_PACK_CONFIG`. Every value that differs per app is set here and nowhere else (product name, menu items, theme switch on or off, sign-out, job URLs when the pack has job components). It must contain the text `productName: "my-app"` exactly; `install.py --name` finds this string and replaces it.
- `tokens/layout.example.tsx`: a root layout that loads the fonts with `next/font/local` (`localFont({ ... })`; `build-view.py` adds `preload: false` to each call), imports `./globals.css`, sets `metadata.title` from `UI_PACK_CONFIG.productName`, and, when the pack has a theme switch, runs the theme script before first paint with `suppressHydrationWarning` on `<html>`.
- `tokens/vitest.config.example.mts`: maps `@` to `src` and includes `tests/**/*.test.ts`.
- `gallery/page.example.tsx`: a page that renders the page title and `<Gallery />`. It is installed as `{src}/app/design/page.tsx` and is not added to the menu.
- `components/design/Gallery.tsx`: exports the gallery component named in `viewer.gallery`. Each gallery card is a `<section>` with an `<h2>` title inside it. `gallery-check.mjs` finds the cards by `section h2`, uses the `<h2>` text as the card's key, and pairs the elements inside in document order, so titles must be unique and the gallery must render the same markup in the pack viewer and in a target. Gallery copy is sample wording not tied to any domain, written in the language of the apps the pack is for, and every control in it works.
- `tests/`: at least a test that checks the token values and their contrast.
- `lib/theme.ts`: only when the pack has a theme switch.
- Fonts: only openly licensed fonts, with the license file, in `fonts/`. When the pack must render Korean and its font has no Hangul glyphs, add a Hangul font (Pretendard, OFL) as the next font in the stack.

Component names: when a pack has a component of a kind the mapping table of the `ui-pack` skill names, it uses that name (`AppShell`, `PageTitle`, `Panel`, `ItemCard`, `StatusMark`, `EmptyState`, and in `ui.ts` `primaryButton`, `secondaryButton`, `dangerButton`, `textButton`, `textLink`, `textInput`), because the mapping table finds components by these names. A pack does not have to have all of them.

The pack viewer is built with the versions in `viewer/package.json` as a static export (`output: "export"`), so everything the gallery imports must build without a server.

## Design guide (`guide/ui-direction.md`)

The design guide is written in the language of the apps the pack is for. It starts with a pack note and has ten numbered sections. Component comments refer to these section numbers, and `SKILL.md` refers to sections 2, 8 and 10 by number, so keep the numbering.

**Pack note** (a blockquote at the very top, before the title). It says:

- where the document comes from (carried over from a source project's design guide, or rebuilt from screens, and from what kind of input);
- that the target copies it to `docs/design/ui-direction.md` and then edits it in this order;
- **kept as is**: which sections' values and rules do not change (normally 3, 4, 5, 6, 7, the sentence rules of 8, and 10);
- **adapted to the target product**: normally the screen definition sentence of section 1, the examples of section 2 and the word table of section 8, and which identity elements are used only when the target has that concept;
- **removed as product-only**: tokens, terms and document references that belong to the source product only;
- that "section N" in component comments means a section of this document;
- that item 5 of section 10 is a check done when the pack is made and is not repeated when the pack is applied.

| Section | Content |
| --- | --- |
| 1. What this screen reads as | One sentence that defines the screen and its user |
| 2. Identity | The few elements that make the design recognizable, and the meaning of the accent color |
| 3. Color | Token values per theme, where each is used, contrast |
| 4. Type | Font, size steps, weights |
| 5. Spacing and shape | Spacing steps, radius, elevation |
| 6. Component rules | When each component is used and its states |
| 7. Motion | Durations, easing, reduced motion |
| 8. Wording | Sentence rules, and a word table of the terms the product uses |
| 9. Reasons for the decisions | One line per decision. A pack made without source code separates measured values, values set differently from the source, estimated values, and things the pack decided because the source did not have them |
| 10. Pre-delivery checks | The checks to run before handing over a screen: (1) run it and press every control, (2) both themes, wide and phone width, (3) keyboard only and focus ring, (4) empty, loading and error states, (5) the design quality checklist, done when the pack is made |

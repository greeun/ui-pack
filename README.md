# ui-pack

A Claude Code skill that applies a saved UI design system pack to another project.

A UI pack is a folder that holds one project's screen design: color, type and spacing tokens, fonts, components, motion, interaction hooks, a design guide, a gallery page and tests. This skill copies a pack into a target project, converts the target's screens to the pack's components and tokens, and verifies that the app still does exactly what it did before. A pack changes how an app looks and responds, not what it does: visible text, element roles, link targets, keyboard behavior and the like (the "app contract") are compared before and after.

The skill also lists the packs you have and opens a pack viewer for each: one HTML file with the live component gallery, the design guide and the install details.

**This repository contains no packs.** It holds the skill, its scripts, the pack viewer template and the component catalog. Packs are made with the companion skill [ui-pack-create](https://github.com/greeun/ui-pack-create) (from a project's source code, a website URL, an SNS post, a screenshot or a video) and are kept in the pack store described below.

## Install

Clone the repository and link it into your Claude Code skills folder:

```bash
git clone https://github.com/greeun/ui-pack.git
ln -s "$(pwd)/ui-pack" ~/.claude/skills/ui-pack
```

Then ask Claude Code to "list packs", "view pack <name>" or "apply pack <name>", or use `/ui-pack list`, `/ui-pack view [pack]`, `/ui-pack apply <pack>`.

## Where packs live

Packs are kept in a pack store, outside this repository:

- default: `~/.axt/vault/ui-pack/packs/<pack>/`
- override: set the environment variable `UI_PACK_HOME`; packs are then read from `$UI_PACK_HOME/packs/<pack>/`

`$UI_PACK_HOME/packs/index.html` is the pack index (every pack with preview images and a component × pack table), and `$UI_PACK_HOME/packs/<pack>/view/index.html` is the pack viewer of one pack. Both are generated by `scripts/build-view.py`.

The pack format (folder layout, `pack.json`, required tokens, design guide sections) is in [references/pack-format.md](references/pack-format.md).

## Requirements

- Node.js 22 or later
- Python 3
- pnpm (used to build the pack viewer)
- Google Chrome, at the default macOS path `/Applications/Google Chrome.app` (screen captures and the gallery comparison run it headless)
- A target project on React 19+, Next.js 16+ (App Router) and Tailwind CSS 4+, or whatever the pack's `requires` says. For another stack the skill carries over tokens, fonts and the design guide only

The scripts were written and used on macOS.

## Contents

| Path | What it is |
| --- | --- |
| `SKILL.md` | The skill: the app contract, the apply procedure, verification, common mistakes |
| `references/pack-format.md` | The pack format |
| `catalog.json` | The component catalog: 81 components a UI pack is expected to cover. Each pack records a status per component (`present`, `rules-only`, `absent`, `unused`) |
| `viewer/` | The Next.js template the pack viewer is built from |
| `scripts/install.py` | Copies a pack's files into a target project, installs its dependencies and writes `ui-pack.lock.json`. Run it again safely: files edited after the install are left alone |
| `scripts/fetch.py` | Fetches a published pack (`github.com/<owner>/ui-pack-<pack>`) into the pack store. Refuses a repository with symlinks or an install list that reads outside the pack or writes outside the target, and prints the npm packages the pack installs |
| `scripts/build-view.py` | Builds `<pack>/view/index.html` (the pack viewer), its preview images and the pack index |
| `scripts/compare.py` | Captures screens before and after applying, builds a side-by-side comparison page and reports app contract items that were `removed` or `added` |
| `scripts/gallery-check.mjs` | Compares the target's `/design` gallery with the pack's gallery by computed style, to catch the target's global CSS leaking into pack components |

Each script documents its usage at the top of the file.
